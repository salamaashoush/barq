# @barqjs/compiler-rs

Native (Rust + oxc) JSX compiler for Barq, exposed to JS through napi-rs.

## Status

This package **replaces** `@barqjs/compiler`. The Babel plugin is being deleted, not preserved —
it is not a target, not a baseline, and not a correctness oracle. Its only remaining use is as a
catalogue of which JSX shapes have to be handled at all.

The correctness oracle is the runtime's own JSX runtime (`@barqjs/core/jsx-runtime`): a JSX file
transpiled by Bun/esbuild with `jsxImportSource=@barqjs/core` into `createElement()` calls, run
against the real runtime, is the semantic specification. Compiled output must produce an identical
DOM and must never do more reactive work than that path.

At milestone 1 `transform()` is an identity round-trip (parse → codegen); it emits no reactive code
yet. That is why `native` defaults to `false` in the Vite plugin, and why it flips at milestone 2.

## Build

```sh
bun run build         # napi build --platform --release
bun run build:debug   # napi build --platform  (far faster, same filenames)
bun test              # the differential harness (needs the binding built first)
bun run test          # cargo test && bun test
cargo fmt --check     # rustfmt.toml is committed; CI gates on this
cargo clippy --all-targets -- -D warnings
```

`index.js`, `index.d.ts` and `barq-compiler.<triple>.node` are generated by the build and are
gitignored. Nothing here works until you have run one of the build commands at least once — the
test harness fails with an explicit message rather than a module-resolution error. CI installs a
Rust toolchain and runs `bun run --cwd packages/compiler-rs build` before `bun run test`.

Publishing this package will need `index.js` and `index.d.ts` tracked in git (napi-rs's own
template commits both), because consumers installing from npm have no Rust toolchain. Nothing
publishes it yet, so they stay ignored for now.

A Rust toolchain is required (napi 3.x MSRV 1.88.0). `@napi-rs/cli` needs Node on `PATH`
(`engines: ^20.17.0 || ^22.13.0 || >= 23.5.0`) even when invoked through Bun.

## API

```ts
import { transform } from "@barqjs/compiler-rs"

const { code, map, warnings } = transform(source, {
  filename: "App.tsx",
  sourcemap: true,
  autoComputed: true,
  templates: true,
  ssr: false,
})
```

Option keys are camelCase on the JS side and snake_case in Rust; napi-derive converts them.
`map` is **absent**, not `null`, when no sourcemap was requested — use `result.map ?? null`.
`warnings` holds non-fatal parser diagnostics as `file:line:col: message`; the Vite plugin
forwards them through `this.warn()`. A syntax error throws instead.

`ssr` is per-module in Vite (the same file is transformed once for the client and once for the
server), so the plugin reads it from the transform hook's third argument, not from its own options.

### Deeply nested input

oxc's parser and codegen recurse without a depth limit. `transform()` estimates nesting depth from
a byte scan and moves anything that could overflow the caller's stack onto a thread sized for it,
so a pathological file returns a diagnostic instead of killing the host process with SIGSEGV.
Ordinary files never leave the calling thread. The measured per-level stack costs the sizing is
derived from are recorded in `src/compile.rs`.

## Using it from Vite

```ts
import { barqVitePlugin } from "@barqjs/compiler/vite"

export default defineConfig({
  plugins: [barqVitePlugin({ native: true })],
})
```

`native: true` throws if the binary is missing. There is no silent fallback to Babel.

## Bundling

The generated `index.js` contains ~80 guarded `require()` calls for every platform triple napi-rs
knows about. Mark this package external in any bundler config that touches it:
`build.rollupOptions.external`, `optimizeDeps.exclude`, `ssr.external`.
